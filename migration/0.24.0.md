# Migrating to Axle 0.24.0

0.24.0 adds experimental sub-agent tools, parallel tool execution, tool context
helpers, and several stream behavior changes.

Most applications need no changes unless they rely on specific error-class
behavior or the `onToolCall` fallthrough semantics in `stream()`.

---

## `onToolCall` Fallthrough in `stream()`

A user-provided `onToolCall` returning `null` / `undefined` now falls through to
executing the matching registry tool, matching `generate()`'s existing
semantics. Previously it produced a `not-found` result.

### Before

```typescript
stream({
  provider,
  model,
  messages,
  tools: [myTool],
  onToolCall: async (name, parameters) => null,
  // ^ null meant "not-found" — tool not executed
});
```

### After

```typescript
stream({
  provider,
  model,
  messages,
  tools: [myTool],
  onToolCall: async (name, parameters) => {
    // Return null/undefined to defer to the registry tool.
    return null;
  },
});

// To explicitly block a tool, return an error result:
stream({
  provider,
  model,
  messages,
  tools: [myTool],
  onToolCall: async (name, parameters) => {
    return { type: "error", error: { type: "not-found", message: "Blocked" } };
  },
});
```

### Why

The inconsistency between `generate()` (which fell through) and `stream()`
(which didn't) was confusing. Now both APIs behave the same way.

## `AbortError` → Tool Error

A tool throwing an error whose `name` is `"AbortError"` (e.g. from `fetch()`
timing out) while the run's signal is **still live** is now reported to the
model as an ordinary tool error instead of aborting the entire run.

Previously, any `AbortError` from a tool would terminate the entire stream,
because Axle couldn't distinguish a tool's internal timeout from a user-issued
`handle.cancel()`. Now Axle checks whether the run's signal is still live; if
so, the tool error is reported to the model as a normal failure and the agent
continues.

This is a behavior change that should be invisible unless you were relying on
tool-internal `AbortError`s to kill the run. If you need that behavior, throw
`AxleToolFatalError` instead.

## Sub-agent Tools (Experimental)

`createAgentTool` creates a tool that delegates work to a child agent:

```typescript
import { createAgentTool } from "@fifthrevision/axle";

const codeReviewer = createAgentTool({
  name: "codeReviewer",
  description: "Review code changes and suggest improvements",
  provider,
  model: "claude-sonnet-4-5-20250929",
});
```

Sub-agent events are forwarded as `action:child-event` and rendered as agent
action parts.

---

## Parallel Tool Execution (Experimental)

`parallelize` wraps a tool so that batched calls run concurrently:

```typescript
import { parallelize } from "@fifthrevision/axle";

const parallelWeather = parallelize(weatherTool);
```

---

## Tool Context Helpers

Two new methods are available on `ToolContext`:

- **`ctx.reportUsage(usage)`** — report token/cost usage from external services
  called by the tool. Usage aggregates into `Stats.breakdown` for per-model cost
  reconstruction.
- The flat `Stats.breakdown` map lets you attribute usage across different
  provider/model pairs (e.g. when a tool calls a different LLM).

### Streaming Events

A new `tool:exec-error` stream event fires when a tool call is aborted or errors
fatally:

```typescript
handle.on((event) => {
  if (event.type === "tool:exec-error") {
    console.error(`Tool ${event.name} failed:`, event.error);
  }
});
```

---

## Quick Upgrade Checklist

- If you use `onToolCall` returning `null` in `stream()`, verify the new
  fallthrough behavior matches your intent. Return `{ type: "error", ... }` to
  explicitly block a tool.
- If you rely on tool-internal `AbortError`s to terminate runs, switch to
  `AxleToolFatalError`.
- Sub-agent tools and parallel execution are experimental — their APIs may
  change.

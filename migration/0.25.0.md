# Migrating to Axle 0.25.x

0.25.0 adds a web search fallback, consolidates the Chat Completions vendor
options, improves non-text tool results, and introduces library-wide
configuration via `configureAxle()`.

---

## `providerToolVendor` → `vendor`

The `providerToolVendor` option on the `chatCompletions` provider factory is
renamed to `vendor`. Axle now auto-detects the vendor from the base URL for
OpenRouter and Together, so explicit configuration is often unnecessary.

### Before

```typescript
const provider = chatCompletions("https://openrouter.ai/api/v1", {
  apiKey: process.env.OPENROUTER_API_KEY,
  providerToolVendor: "openrouter",
});
```

### After

```typescript
// Auto-detected — no vendor option needed:
const provider = chatCompletions("https://openrouter.ai/api/v1", {
  apiKey: process.env.OPENROUTER_API_KEY,
});

// Or set explicitly:
const provider = chatCompletions("https://openrouter.ai/api/v1", {
  apiKey: process.env.OPENROUTER_API_KEY,
  vendor: "openrouter",
});
```

### Why

The name `providerToolVendor` was too narrow — the vendor also affects reasoning
translation, file part handling, and tool-call adapter behavior. `vendor` is
shorter and more general. Auto-detection removes the need to set it manually for
well-known endpoints.

The `ChatCompletionsVendor` type is now `"openrouter" | "together"`.

---

## Together Vendor Support

The Chat Completions provider now auto-detects Together
(`api.together.ai`, `api.together.xyz`) and:

- Translates `reasoning: true` → `{ reasoning: { enabled: true } }` (instead of
  `reasoning_effort: "high"` which Together doesn't support).
- Rejects PDF file parts with a clear error (Together Chat Completions does not
  support document file parts).

No configuration changes are required — auto-detection handles it.

---

## Web Search Fallback

Providers that don't natively support `web_search` can now use Axle's fallback
mechanism. Call `configureAxle()` once at startup:

```typescript
import { configureAxle, braveWebSearch } from "@fifthrevision/axle";

configureAxle({
  webSearchFallback: braveWebSearch({ apiKey: process.env.BRAVE_API_KEY! }),
});
```

With this configured, any provider can declare:

```typescript
providerTools: [{ type: "provider", name: "web_search" }],
```

Axle will execute the search client-side and pass results back as tool output.
Native `web_search` support on the provider always takes priority.

If web search is requested but no native support or fallback is configured, Axle
throws `WEB_SEARCH_FALLBACK_NOT_CONFIGURED`.

### Custom Fallback Backend

Implement the `WebSearchBackend` interface for custom search providers:

```typescript
import type { WebSearchBackend } from "@fifthrevision/axle";

const customBackend: WebSearchBackend = {
  name: "my-search",
  async search(request, context) {
    // context.signal for cancellation; context.span for observability
    return {
      results: [
        { title: "Example", url: "https://example.com", snippets: ["..."] },
      ],
    };
  },
};

configureAxle({ webSearchFallback: customBackend });
```

## `AxleConfiguration` and `configureAxle()`

Library-wide configuration is now managed through:

```typescript
import { configureAxle, getAxleConfiguration } from "@fifthrevision/axle";
```

- `configureAxle(options)` — sets configuration. Call once at startup.
- `getAxleConfiguration()` — reads current configuration (used internally).

Currently the only configuration option is `webSearchFallback`, but this is the
seam for future library-wide settings.

## Non-text Tool Results

In 0.24.0, Chat Completions tool results containing non-text file parts
(e.g. images, PDFs returned by a tool) would throw. In 0.25.0, they produce a
descriptive placeholder message instead, warning the model that the file content
was not included. This means the agent continues without crashing, giving the
model a chance to ask the user for the file in a different way.

---

## Syntactically Invalid JSON Tool Parameters (0.25.2)

When a provider sends tool-call arguments that can't be parsed as JSON, Axle now
surfaces them as a tool-call argument error via stream events rather than
throwing. The error carries:

```typescript
{
  type: "invalid-arguments",
  message: "Failed to parse tool call arguments for ...",
  raw: "…truncated buffer…"
}
```

Stream consumers receive `tool:exec-complete` with an error result for the
malformed call. The non-streaming `generate()` path handles this the same way.

---

## OpenAI File Resolution (0.25.3)

OpenAI file parts were incorrectly resolving filenames and URLs in 0.25.0–0.25.2.
0.25.3 fixes this — no code changes required.

---

## Parallelize `maxResultBytes` (0.25.4)

`parallelize()` gained a new `maxResultBytes` option (default 20 MiB). When
total output from batched tool calls exceeds this limit, individual results
are omitted with a descriptive marker so the model can still process partial
results:

```typescript
const parallelWeather = parallelize(weatherTool, {
  maxResultBytes: 1_000_000, // 1 MB cap
});
```

Larger `maxResultBytes` values allow more results to be returned in a single
batch. Set to `0` to disable the check entirely (not recommended — large
results can cause context blow-up).

## New Models (0.25.5)

0.25.5 adds several new model constants:

**Anthropic:**
- `CLAUDE_SONNET_5` — `"claude-sonnet-5"`
- `CLAUDE_FABLE_5` — `"claude-fable-5"`

Both support 128K output tokens.

**Gemini:**
- `GEMINI_3_5_PRO` — `"gemini-3.5-pro"`

No migration needed — these are purely additive.

---

## Quick Upgrade Checklist

- If you pass `providerToolVendor` to `chatCompletions()`, rename it to
  `vendor`. Most users can drop it entirely and rely on auto-detection.
- If you want web search on providers that don't support it natively, call
  `configureAxle({ webSearchFallback: ... })` at startup.
- If your tool returns non-text files, handle the new placeholder message in
  your model prompting if needed.

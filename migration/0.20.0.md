# Migrating to Axle 0.20.0

0.20.0 is a breaking release focused on the core/CLI boundary.

The core runtime is now the `@fifthrevision/axle` package. The command-line
workflow runner is now the `@fifthrevision/axle-cli` package. The repo remains a
workspace so the CLI can keep dogfooding the current core runtime during
development.

There is no compatibility shim layer.

---

## Package Split

Library consumers should continue importing runtime APIs from
`@fifthrevision/axle`:

```ts
import { Agent, Instruct, anthropic } from "@fifthrevision/axle";
import { TurnAccumulator } from "@fifthrevision/axle/ui";
```

CLI users must now install the new CLI package:

```diff
- npm install -g @fifthrevision/axle
+ npm install -g @fifthrevision/axle-cli
```

The `axle` binary is no longer published by the core package.

---

## Local Tools Moved Out Of Core

The core package no longer exports concrete local workflow tools.

**Removed from `@fifthrevision/axle`:**

- `calculatorTool`
- `execTool`
- `readFileTool`
- `writeFileTool`
- `patchFileTool`
- `braveSearchTool`

Define application tools directly when using core:

```diff
- import { Agent, calculatorTool } from "@fifthrevision/axle";
+ import { Agent } from "@fifthrevision/axle";
+ import type { ExecutableTool } from "@fifthrevision/axle";
+ import { z } from "zod";
+
+ const myTool: ExecutableTool = {
+   name: "lookup",
+   description: "Lookup information",
+   schema: z.object({ key: z.string() }),
+   async execute(input) {
+     return "result";
+   },
+ };

- const agent = new Agent({ provider, model, tools: [calculatorTool] });
+ const agent = new Agent({ provider, model, tools: [myTool] });
```

CLI job files can still use these local tool names:

- `calculator`
- `exec`
- `patch-file`
- `read-file`
- `write-file`

---

## Memory And Store Implementations Moved To CLI

Core keeps only the memory and store interfaces:

```ts
import type { AgentMemory, FileStore } from "@fifthrevision/axle";
```

`ProceduralMemory` and `LocalFileStore` are no longer part of the core runtime
package. Provide your own memory and persistence implementations, or use the
CLI behavior through job files.

`AgentConfig` no longer has `scope` or `store`. `Agent` owns a stable
`sessionId`, and memory receives that id via `MemoryContext`.

```diff
- import { Agent, ProceduralMemory, anthropic } from "@fifthrevision/axle";
+ import { Agent, anthropic } from "@fifthrevision/axle";
+ import type { AgentMemory, MemoryContext } from "@fifthrevision/axle";
+
+ class MyMemory implements AgentMemory {
+   async recall() { return {}; }
+   async record(ctx: MemoryContext) { /* ... */ }
+ }

  const agent = new Agent({
    provider,
    model,
-   memory: new ProceduralMemory({ provider, model }),
+   memory: new MyMemory(),
  });
```

## CLI Config Changes

The CLI no longer loads `axle.config.yml`, `axle.config.yaml`, or JSON config
files.

Provider secrets should come from the environment or a local `.env` file:

```bash
OPENAI_API_KEY=...
ANTHROPIC_API_KEY=...
GEMINI_API_KEY=...
```

Optional model overrides:

```bash
OPENAI_MODEL=gpt-4.1
ANTHROPIC_MODEL=claude-sonnet-4-5-20250929
GEMINI_MODEL=gemini-2.5-pro
```

OpenAI-compatible endpoints:

```bash
CHATCOMPLETIONS_BASE_URL=http://localhost:11434/v1
CHATCOMPLETIONS_MODEL=llama3
CHATCOMPLETIONS_API_KEY=...
```

Provider-level fields in the job file override environment defaults:

```yaml
provider:
  type: openai
  model: gpt-4.1
```

To use a non-standard environment variable, use `apiKeyEnv`:

```yaml
provider:
  type: openai
  apiKeyEnv: CUSTOM_OPENAI_KEY
```

---

## CLI Job Files

The CLI now requires an explicit YAML job file:

```bash
axle -j path/to/job.yml
```

**Removed:**

- Default `axle.job.yml` / `axle.job.yaml` lookup
- JSON job files
- `-c, --config` flag

Use `.yml` or `.yaml` job files only.

## Agent Definition And Session APIs

0.20.0 introduces serializable agent/session types for save/resume workflows:

- `AgentDefinition` — serializable recipe (provider, model, tools, request defaults)
- `AgentSession` — continuation and render state (messages, turns, sessionId)
- `SavedAgent` — `{ definition, session }` pair for persistence
- `createAgentConfig(definition, resolver)` — resolves a definition into runtime config
- `agent.snapshot()` — captures current session state
- `agent.restore(session)` — restores a previously captured session

`AgentDefinition` is not executable by itself. The host resolves providers and
tools into an `AgentConfig` via a resolver function:

```ts
import { Agent, createAgentConfig, anthropic } from "@fifthrevision/axle";
import type { AgentDefinition, AgentDefinitionResolver, SavedAgent } from "@fifthrevision/axle";

const definition: AgentDefinition = {
  version: 1,
  name: "my-agent",
  provider: { type: "anthropic" },
  model: "claude-sonnet-4-5-20250929",
};

const resolver: AgentDefinitionResolver = async (def) => ({
  provider: anthropic(process.env.ANTHROPIC_API_KEY!),
});

// Reconstruct from a saved payload
const saved: SavedAgent = await db.load(sessionId);
const config = await createAgentConfig(saved.definition, resolver);
const agent = new Agent(config);
agent.restore(saved.session);

// Continue the conversation
await agent.send("What did we discuss?").final;
```

See [Hosting & Sessions](/guide/hosting) for the full pattern.

## What Did Not Change

- **Provider API** (`anthropic()`, `openai()`, `gemini()`, `chatCompletions()`) — unchanged.
- **`Agent.send()`** — unchanged.
- **`Instruct`** — unchanged.
- **`generate()` and `stream()`** — unchanged.
- **`MCP`** — unchanged.
- **Tool interface (`ExecutableTool`)** — unchanged.
- **Event model (`TurnEvent`, streaming events)** — unchanged.
- **Result shape (`ok`, `response`, `usage`)** — unchanged.
